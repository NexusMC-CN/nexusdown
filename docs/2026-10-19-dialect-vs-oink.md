# 方言清单 vs OINK 21 组件 —— 统计、映射与风格统一

> 统计时间：2026-10-19。对象：`nexusdown` 当前 `src/cm` + `src/render` 的方言实现，
> 对照 [OINK](https://oink.pgsty.com/) v1.3.2 的组件手册。
>
> 目的不是「抄 21 个组件」，而是回答三个问题：
> **我们现在有什么、它有什么值得拿、我们的语法哪里不体面。**

---

## 0. 结论先行

| 结论 | 内容 |
| --- | --- |
| 现有方言 | 标准 Markdown + GFM 全量，外加 **11 类自定义/半自定义语法** |
| 最大差距 | 不是组件数量，是**块级变体语法**（属性行 `{…}`）——缺了它，每加一个组件都要新造一种围栏 |
| 最大内部不一致 | 块级数学用 ` ```math `、行内用 `$…$`；embed 用三 token info string |
| 可吸收 | OINK 21 个里：**8 个直接吸收、5 个改造后吸收、3 个可选运行时、5 个不适合** |
| 建议顺序 | 先补「属性行」这一层基础设施，再铺组件；`$$` 数学与 callout 可以立刻做 |

## 1. 我们现在的语法（统计）

### 1.1 标准 Markdown / GFM（全量）

| 语法 | 编辑器侧 | 渲染侧 |
| --- | --- | --- |
| 标题（ATX / Setext） | 字号、`#` 淡化、行级揭示 | `<h1>`–`<h6>` |
| 段落 / 软换行 | 原文 | `<p>` |
| `**粗**` `*斜*` `~~删~~` `` `码` `` | 样式 mark + 标记揭示 | `<strong>` `<em>` `<del>` `<code>` |
| 链接 / 图片 | 链接淡化、图片 widget | `<a>` `<img>`（URL 白名单） |
| 引用块 | 左侧竖线 | `<blockquote>` |
| 有序 / 无序列表 | 列表符淡化 | `<ol>` `<ul>` |
| 分割线 | 渲染 | `<hr/>` |
| 围栏代码 | 语言头 + 复制 + 折叠 | `<pre><code>` + 代码头 |
| 缩进代码 | 未特殊处理 | `<pre><code>` |
| 表格（GFM） | 表头加粗、`\|` 淡化，**无单元格编辑** | `<table>`（支持 `:---:` 对齐） |
| 任务列表（GFM） | **可点击复选框** | `<input type="checkbox">` |
| 自动链接 | 裸 URL / `www.` 淡化 | `linkify` + `wwwOnly` 收窄 |
| 原始 HTML | — | **禁用**（`html: false`，XSS 线） |

### 1.2 自定义方言（11 类）

| # | 语法 | 形式 | 编辑器侧 | 渲染侧 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 高亮 | `==文本==` | 行内 mark + 揭示 | `<mark>` | 与 Obsidian 一致；GitHub 不认，显示字面量 |

| 4 | 块级数学 | ` ```math ` 围栏 | 块级 replace + 点开揭示 | KaTeX | **与行内 `$` 不一致**（见 §4.1） |
| 5 | 提及 | `@slug` / `@slug#fragment` | 行内胶囊；独占段落 → 卡片 | 胶囊 / 卡片 / 墓碑 | 数据走 `RenderData.mentions`，库不查库 |

| 8 | 轮播 | 同一段落连续图片 | 每张独立 widget + `1/3` 提示 | 零 JS `scroll-snap` | 不新增语法 |
| 9 | 代码块增强 | 围栏 | 语言头 / 复制 / 折叠 | 同构代码头 | 两侧共用 `code-header-parts` |
| 10 | URL 白名单 | 链接 / 图片 | 同策略 | 同策略 | 防 `javascript:` 等 |
| 11 | 提及补全 | 打 `@` 弹候选 | CM6 autocomplete | — | 消费方须装 `@codemirror/autocomplete` |

### 1.3 编辑器专属能力（不是语法，但构成体验）

行级揭示（Obsidian 式）、围栏折叠、工具栏、快捷键、输入法门控、块级「点开才揭示」、滚动位置锁定。

### 1.4 我们已有、OINK 没有的

- **行级揭示 / 就地编辑**（OINK 是静态站，没有编辑器）
- **`@` 就地补全**、**任务复选框可交互**
- **零 JS 轮播**（`scroll-snap` + 锚点）
- **三家平台 embed + 长链自动识别**（OINK 没有 embed 类组件）
- **提及墓碑**（目标删除后的降级形态）
- **库不联网**：外站数据一律由消费方经 `RenderData` 注入

## 3. 映射：哪些能用到我们这儿

判定标准三条：

1. **能不能在编辑器里实时揭示**（我们不是静态站，块级组件要能被点开看源码）；
2. **渲染侧能不能零 JS 降级**（我们的渲染器是同步、DOM-free 的，不能依赖运行时）；
3. **数据从哪来**（库不联网，外部数据必须走 `RenderData`）。

| OINK 组件 | 我们的对应 | 建议 | 成本 | 优先级 |
| --- | --- | --- | --- | --- |
| **Callouts** | 无 | ✅ **直接吸收** `> [!NOTE]`，GitHub 兼容，10 种类型 = 图标 + 色板 | 低 | **P0** |
| **Math** | `$…$` + ` ```math ` | ✅ 增加 `$$…$$` 正典；围栏保留为别名 | 低 | **P0** |
| **Code Blocks** | 已有语言头/复制/折叠 | ✅ 补 `{title=… lines=…}` 属性（属性行到位后） | 低 | P1 |
| **Steps** | 无 | ✅ `{.steps}` 列表变体，零运行时 | 低 | P1 |
| **Cards** | 无 | ✅ `{.cards}` 链接列表变体，零运行时 | 低 | P1 |
| **Badge** | 无 | ✅ 行内角色 `[Beta]{.badge}` 或 `:badge[Beta]`（不用 shortcode） | 低 | P1 |
| **Kbd** | 无 | ✅ 行内角色 `:kbd[Ctrl K]` | 低 | P1 |
| **Tabs** | 无 | ✅ `{tab="Linux"}` 相邻围栏分组；编辑器里是一个块级组 | 中 | P1 |
| **Fields** | 无 | ✅ `{.fields}` 表格变体（参数文档），零运行时 | 低 | P2 |
| **Tables** | GFM 表格 | ✅ 补 `{caption=…}` / `{.full-width}` | 低 | P2 |
| **FileTree** | 无 | ✅ ` ```filetree ` 围栏，零 JS（`<details>` 折叠） | 中 | P2 |
| **Gallery** | 轮播（连续图片） | ✅ 用 ` ```gallery ` 围栏表达「带说明/链接的图集」，复用现有轮播 | 中 | P2 |
| **Mermaid** | 无 | ⚠️ 改造后吸收：渲染侧只出 `<pre data-mermaid>` 占位，消费方按需加载 | 中 | P1 |

| **Includes** | 无 | ❌ 跳过（构建期文件系统语义，论坛内容在库里） | — | — |

## 4. 现有语法哪里不体面

### 4.1 块级数学与行内数学不一致（最明显）

- 行内：`$E=mc^2$`；块级：` ```math ` 围栏。
- 理由（`dialect-extensions.md` 第 2 节）是**工程上的**：`$$` 要两侧各写一个块级解析器，围栏两侧已经解析好了。
- 但作者视角这是**两套语法记一件事**，而且 ` ```math ` 在 GitHub 上不会渲染成公式。
- **建议**：`$$…$$` 定为块级正典，` ```math ` 保留为别名（渲染侧加一条 block rule，编辑器侧在块级通道里识别 `$$` 段落）。`$$` 与行内 `$` 的边界规则写死（开 `$` 后不能是空白、闭 `$` 前不能是空白）。

### 4.2 Embed 的三 token info string 太 ad hoc

` ```embed bilibili video BV1xx411c7mD ` —— 位置参数、平台名、类型名都得记。

- 我们**已经有** `parseEmbedUrl()` 和长链自动识别，直接复用即可。
- **建议**：正典改为 URL 形式 ` ```embed https://www.bilibili.com/video/BV… `；三 token 形式保留为 legacy 别名。这样「贴链接 → 自动 embed」和「强制 embed」是同一条解析路径。

### 4.3 缺「变体层」，每加一个组件都要新造语法

现在加一个组件 = 新围栏名 + 新 info 解析 + 两侧实现。OINK 用**一行属性**解决了 8 个组件的变体（steps / cards / fields / tabs / 表格标题 / 代码标题 / 图片尺寸 / 全宽）。

- **建议**：引入属性行 `{…}`（紧贴块后一行），作为唯一的「变体/参数」通道。
- 这是**一次性基础设施投入**，之后 steps/cards/fields/tabs/代码标题全部变成「同一套解析 + 不同渲染」。

### 4.4 「独占段落」语义只用在了一半

链接卡片、提及卡片、轮播都用「段落位置」表达形态，很优雅。但 **embed 是围栏**，同一个「贴一个链接」的意图有两种写法。

- **建议**：独占段落的平台链接 → 自动 embed（渲染侧已有 `resolveEmbedFromText`，编辑器侧也有自动识别）；围栏只用于**强制**指定。

### 4.5 其他小问题

| 问题 | 现状 | 建议 |
| --- | --- | --- |
| `:emoji:` 与时间/比例冒号 | 只在已知表命中（好） | 补词边界与 `\:` 转义，文档写明 |
| `$…$` 与价格 | 需边界规则 | 写死「开 `$` 后非空白、闭 `$` 前非空白」，与 KaTeX 站点一致 |
| 提及编辑器显示 slug、渲染显示标题 | 刻意（编辑器提示语法） | 保持，但文档明确「这是编辑器提示，不是预览」 |
| 表格无 caption / 全宽 | GFM 只有对齐 | 属性行到位后补 `{caption=…}` |
| 代码块无行号 / 标题 | 只有语言头 | 属性行到位后补 |
| 任务列表无进度汇总 | 可交互复选框 | 可选：段落末尾 `[3/5]` 角标 |

## 5. 统一风格：四层语法模型

把「一个语法该长什么样」收敛成四条规则，新组件按层落位：

| 层 | 用途 | 形式 | 例子 |
| --- | --- | --- | --- |
| **L1 行内定界符** | 行内语义 | 成对符号 | `**粗**` `*斜*` `~~删~~` `==高亮==` `$数学$` `:smile:` `@slug` `[文本](url)` |
| **L2 围栏** | 块级构造 | ` ```类型 … ` | ` ```math ` ` ```embed ` ` ```mermaid ` ` ```filetree ` ` ```gallery ` ` ```echarts ` |
| **L3 属性行** | 变体 / 参数 | 紧贴块后的 `{…}` | `{.steps}` `{.cards}` `{.fields}` `{tab="Linux"}` `{caption="…"}` `{title="a.ts" lines=1-20}` |
| **L4 段落位置** | 布局语义 | 独占段落 / 连续块 | 独占段落链接 → 卡片；独占段落提及 → 卡片；连续图片 → 轮播；独占段落平台链接 → embed |

### 5.1 四条硬规则

1. **不引入 shortcode。** `{{< … >}}` 是 Hugo 的构建期机制，进不了纯 Markdown 内容，也进不了编辑器。等价能力一律用 L1–L3 表达。
2. **每个块级语法必须有三种形态**：编辑器揭示态 = 源码；渲染侧无 JS 降级（占位/`<pre>`/静态 HTML）；Markdown 输出保留源码（供 RSS / AI / 复制）。
3. **属性行必须「最坏情况只多一行字面量」**：在 GitHub 上 `{.steps}` 会显示成一行字，但不破坏可读性——这是可接受的代价。
4. **命名统一**：围栏名 kebab-case；属性键 kebab-case；类名 `nd-*`；功能名两侧同名（已有约定）。

### 5.2 运行时边界（Mermaid / ECharts 类）

我们渲染器是**同步、DOM-free、零运行时**的。这类组件按下面的契约接：

- 渲染侧只输出**占位结构** + `data-*`（源码原样放在 `<pre>` 里，SSR 可读、可复制、可被 AI 读）；
- 消费方（论坛前端）决定是否加载运行时、何时加载；
- 没有运行时 = 退化成代码块，**不报错、不空白**。

## 7. 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 属性行解析 | lezer 不认属性行；markdown-it 需要 attrs 插件或自定义 rule | 先做「扫描层」而不是 lezer 扩展：两侧各一个扫描函数，共用同一份 `src/shared/attrs.ts` |
| 两侧实现税 | 每加一个组件仍要写两遍（编辑器 + 渲染器） | 先做上次讨论的「方言单一事实源 + parity fuzz」，再铺组件 |
| 运行时组件 | Mermaid/ECharts 与零运行时原则冲突 | 按 §5.2 的占位契约，运行时永远在消费方 |
| 语法膨胀 | 21 个全收会让方言变成「第二个 Markdown」 | 只收 §3 里 P0–P2 的 13 个，其余明确不做 |

### 8.1 `renderMarkdown` 在 120 段压力样例上的耗时

| 项 | 值 |
| --- | --- |
| 样例 | `playground/src/fixtures.ts` 的 `stress`（120 段：标题 + 粗 / 斜 / 行内码 / 高亮 / 链接） |
| 源大小 | 15 035 B · 480 行 |
| 产出 HTML | 30 876 B |
| 耗时（**5 次中位数**） | **8.5 ms**（另一独立进程复测 9.3 ms） |
| 单次波动 | 7.2 – 26.2 ms（最慢那次是**首次**调用，含 JIT 预热与解析器构建） |
| 环境 | Windows / Node v22.22.3 / `dist/render/index.js`（构建产物，不是 `src/`） |

测法（一次性脚本，**不进仓库** —— 微基准容易脆，任务书也不要求）：

```js
const runs = Array.from({ length: 5 }, () => {
  const t = performance.now()
  renderMarkdown(stress)
  return performance.now() - t
})
runs.sort((a, b) => a - b)
runs[2] // 中位数
```

⚠️ 只报中位数、不报「最快」：首次调用带 JIT 预热，和稳态不是一个量级。

### 8.2 大文档滚动 / 折叠有没有可见跳变

⚠️ **未人工实测。** 本次实现跑在无浏览器的环境里（`jsdom` 只能验装饰的区间与种类，
验不了滚动位置），所以这一条**没有结论**，只有可核对的事实与待办：

- **代码层面的防线**（`src/cm/plugin.ts` 的 `NexusdownLivePreview.update`）：
  每次重建装饰前记下 `scrollTop` / `scrollLeft`，重建后**同步恢复一次**，
