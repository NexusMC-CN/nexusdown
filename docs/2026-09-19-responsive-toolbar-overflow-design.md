# 响应式工具栏动态收纳设计

## 背景

当前工具栏使用单行 `flex` 和 `overflow-x: auto`，同时隐藏了滚动条。在窄容器、平板竖屏和手机上，后半部分工具虽然仍在滚动区域内，但界面没有明确的可滚动提示，鼠标用户也很难发现或访问它们。

本设计采用已确认的 A1 方案：工具栏保持单行，根据编辑器容器的真实可用宽度，把放不下的工具动态收进右侧“更多”菜单。

## 目标

- 在任意编辑器宽度下都能访问全部工具。
- 工具栏保持单行，不挤占富文本和 Markdown 编辑区域的高度。
- 按容器宽度响应，而不是按设备型号或固定页面断点判断。
- 保留现有工具顺序、分组、激活态、禁用态、只读态和自定义工具能力。
- 复用现有顶层浮层、主题同步和可视视口定位能力。
- 支持鼠标、触屏和键盘操作，并兼容 SSR。

## 非目标

- 不修改 Tiptap 命令、Markdown 转换或 core 会话行为。
- 不增加另一套移动端工具配置。
- 不按设备型号维护固定的按钮白名单。
- 不改变 `toolbarItems` 的现有数据结构和调用方式。

## 响应式行为

工具栏分为可裁切的主轨道和固定在右侧的“更多”触发区。主轨道仍按现有顺序渲染全部控件；宽度充足时全部显示，宽度不足时从右向左把超出边界的控件标记为收纳项。

“更多”区域的宽度在计算溢出时预留，按钮本身仅在确实存在收纳项时显示，因此宽屏状态不会出现空菜单。按钮一旦出现，就固定在工具栏右侧，不会随主轨道滚走。

撤销、重做、查找和粘贴模式位于序列最前端，会自然获得最高显示优先级。极窄宽度下只有“更多”按钮是强制保留项；其他工具仍可进入菜单，避免固定按钮集合反过来造成新的裁切。

调用方通过现有 `toolbarItems` 调整顺序时，新的顺序同时决定显示优先级。自定义分组和自定义按钮自动参与测量和收纳，不需要额外配置。

## 组件边界

### `EditorToolbar.vue`

负责把现有工具项、查找按钮和粘贴模式按钮组织成统一的可渲染控件序列，协调主轨道、测量结果和“更多”菜单。它不直接实现具体 Tiptap 命令。

### `ToolbarControl.vue`

负责渲染单个工具控件。普通命令、标题、颜色、高亮、链接和图片在主轨道与“更多”菜单中复用同一个渲染入口，防止两处逻辑、禁用态或事件行为发生偏差。

该组件支持两种表现：

- `compact`：主工具栏中的纯图标形式。
- `overflow`：“更多”菜单中的图标加文字形式，便于触屏识别。

### `ToolbarOverflowMenu.vue`

负责“更多”按钮、顶层菜单、菜单定位、主题变量、外部点击关闭和键盘焦点。菜单按原工具组展示当前收纳项，不显示仍位于主栏的工具。

### `useToolbarOverflow.ts`

仅负责测量与分类：监听工具栏容器宽度，读取真实控件边界，产出 `overflowedKeys`。它不了解具体命令，也不执行编辑操作，便于使用模拟尺寸进行独立测试。

## 测量算法

1. 主轨道渲染全部控件，并给每个控件稳定的 key 和测量包装元素。
2. 控件即使被收纳也保留在主轨道布局中，只使用 `visibility: hidden`、`pointer-events: none` 和 `aria-hidden` 隐藏，因此其真实宽度仍可读取。
3. 先用完整工具栏宽度判断是否存在溢出；没有溢出时不显示“更多”按钮。
4. 存在溢出时预留“更多”触发区宽度，再根据每个控件的右边界确定收纳集合。
5. 分隔线不作为独立工具进入菜单；主栏只在相邻可见分组之间显示分隔线，菜单使用分组标题表达结构。
6. `ResizeObserver` 监听编辑器工具栏容器；变化后在下一帧合并测量，避免连续 resize 造成重复布局计算。
7. 浏览器不支持 `ResizeObserver` 时，挂载后测量一次并回退到 `window.resize`。脚本尚未挂载或测量失败时保留横向滚动作为最低能力，不让工具彻底不可访问。

该算法读取实际 DOM 尺寸，所以宿主修改按钮宽度、字体、间距或触屏尺寸后仍能正确判断。

## “更多”菜单交互

- 菜单通过 `Teleport` 挂载到 `body` 或最近的原生模态 `dialog`。
- 使用 `position: fixed`、可视视口边缘约束和上下翻转，不被编辑器的 `overflow: hidden` 裁切。
- 复用 `useNexusdownViewport`、`useNexusdownOverlayTheme`、`resolveOverlayTarget()` 和 `nexusdownThemeVariables()`。
- 每个收纳项显示 Iconify 图标和文字标签；触屏目标至少为 44x44 CSS px。
- 打开时聚焦第一个可用项；ArrowUp、ArrowDown、Home、End 在菜单内移动焦点；Escape 关闭并把焦点还给“更多”按钮。
- 普通命令执行后关闭菜单。标题、链接和图片等复合控件允许打开现有二级浮层；应用或取消后再回到“更多”菜单。
- 外部点击关闭时，二级浮层被视为同一浮层链的一部分，点击二级内容不会提前卸载它的触发组件。
- 只读模式继续显示工具状态，但所有会修改内容的入口保持禁用。

## 状态与数据流

`EditorToolbar` 从 `items` 和 `ToolbarContext` 生成稳定控件序列。`useToolbarOverflow` 仅返回收纳 key；主栏和菜单按 key 过滤同一序列。命令仍通过现有 `execute()`、`executeHeading()`、`executeLink()` 和 `executeImage()` 路径进入 session，并继续触发 `executed` 事件。

选择变化、命令执行和粘贴模式变化仍沿用现有响应式刷新逻辑。“更多”菜单不缓存 Tiptap 状态，每次渲染直接读取当前 `ToolbarContext`，避免主栏和菜单的激活态不一致。

## 样式与定制

主栏新增稳定类名用于轨道、测量包装和更多触发区；菜单新增独立类名用于容器、分组、标签和条目。颜色、边框、阴影继续使用 `--nexus-*` 主题变量。

调用方现有的 `toolbarItems` 与 CSS 覆盖方式保持有效。不新增必填 prop，也不改变默认工具集合。`src/style.css` 与 `public/style.css` 必须保持字节一致。

## SSR 与异常边界

- setup 阶段不直接访问 `window`、`document` 或 `ResizeObserver`。
- SSR 输出完整主工具栏，不输出依赖客户端尺寸的收纳判断；挂载后完成首次测量。
- 卸载时断开 `ResizeObserver`、resize、pointer 和 keydown 监听。
- 工具项在打开菜单期间被调用方移除时，菜单重新计算并把焦点退回“更多”按钮；没有剩余收纳项时自动关闭。
- 宽度变化导致当前聚焦项回到主栏时，菜单关闭并把焦点移到该工具的新主栏实例。
- 宽度变化导致主栏中已打开的复合工具进入收纳区时，该工具先关闭自己的浮层，避免菜单继续锚定到不可见按钮。

## 测试与验收

### 自动化测试

- 宽容器下全部工具位于主栏，不显示“更多”。
- 窄容器下尾部工具进入菜单，主栏没有水平裁切或页面溢出。
- 容器从宽变窄、再变宽时收纳集合可逆，编辑器高度不变化。
- 自定义分组、自定义按钮和自定义 CSS 宽度参与真实测量。
- 菜单中的普通命令、标题、颜色、高亮、链接、表格和图片保持原行为。
- 激活态、禁用态、只读态和粘贴模式在主栏与菜单中一致。
- 键盘导航、Escape 焦点恢复、外部点击和二级浮层链正确。
- 模态 `dialog`、亮暗主题、SSR 和监听器清理保持有效。
- 两份发布样式合同继续通过。

### 浏览器验收

在 1280px、900px、760px、390px 和 320px 宽度下检查：

- 所有工具都能从主栏或“更多”菜单访问。
- 工具栏始终单行，编辑器高度和页面滚动高度不因菜单变化。
- 不出现横向页面溢出，触屏目标不小于 44px。
- 菜单及二级浮层不会被编辑器、状态栏或双栏容器裁切。
- 亮色、暗色和宿主自定义皮肤一致。
